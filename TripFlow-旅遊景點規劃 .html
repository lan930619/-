01 / 生活痛點與專題動機

景點存了很多，
行程怎麼排？

旅遊景點規劃工具
把想去的地方，整理成每天看得懂的行程。

旅遊規劃情境：景點分散在社群收藏、地圖與聊天訊息中，安排時必須反覆查找名稱、估算停留時間，再手動核對每天的時間與花費。

輸入日期、景點、停留與交通時間，自動計算每站抵達與離開時間，並整理當日預估花費。

02 / 產品需求規格

以「每日行程」作為規劃單位

輸入欄位與限制

欄位 規則
行程日期 必填，依日期分組。
景點名稱／地點 名稱必填 1～60 字；地點或地址選填，最多 120 字。
景點類型 景點、美食、購物、住宿，四選一。
停留時間 15～720 分鐘，15 分鐘為單位。
到本站交通時間 0～360 分鐘，整數；第一站從出發地計算。
預估費用 0～100,000 元，整數新臺幣；自行填入同一人數範圍的費用。
備註 選填，最多 200 字。

處理邏輯與輸出

每日設定：選定日期後設定出發時間與預算，預設 09:00、2,000 元。

時間計算：第一站抵達＝出發時間＋交通時間；離開＝抵達＋停留；下一站以其前站離開時間繼續累加。

順序調整：新增景點排到當日最後，可上移、下移；調整後重新計算所有時間。每站交通估計需自行確認。

結果：顯示景點數、交通加停留的總時數、預估費用；超出預算或跨午夜時提示。日期切換只顯示當日行程。

其他操作：編輯、確認刪除、本機保存、下載 JSON 備份，以及開啟景點地圖搜尋。

範圍說明：這是協助整理行程的工具，不提供即時交通、營業時間、票價、訂房或最佳路線計算。地圖按鈕需連網，並以輸入的名稱與地址搜尋；資料不代表已驗證的旅遊資訊。
03 / 完整 Prompt

將旅遊需求轉成可實作的規格

本作品的整理版實作提示詞，可用來重建原型；不是宣稱使用者曾逐字送出的歷史對話。 

請扮演前端工程師，製作「TripFlow 旅遊景點規劃工具」，解決景點收藏分散、行程安排過滿與花費不易核對的問題。

交付：單一 HTML，內嵌 CSS 與 JavaScript，繁體中文，不依賴外部套件、字型或 API，離線可使用。做成六頁簡報：生活痛點、需求規格、完整 Prompt、迭代檢查、互動成果、成果與心得。提供按鈕與左右鍵換頁，輸入欄位操作時不得誤換頁；手機採單欄排版。

介面：藍綠色與米白卡片式設計。第五頁包含日期選擇、當日出發時間、當日預算、景點數／總時數／費用統計。左側景點表單，右側以時間軸顯示選定日期的行程。初次開啟清單為空，可按鈕加入明確標示的示範資料。

欄位：景點日期必填；名稱去除前後空白後為 1～60 字；地址選填且最多 120 字；類型為景點／美食／購物／住宿。停留 15～720 分鐘且為 15 的倍數；到本站交通時間 0～360 分鐘整數；費用 0～100000 元整數，以新臺幣估算；備註最多 200 字。每筆具有獨立 ID。每日設定以日期為鍵，出發時間預設 09:00，預算預設 2000 元，可設定 0～1000000 元整數。

邏輯：景點依日期分組，依使用者順序排列。新增排到當日最後；同日編輯保持原位置，改日期時移到新日期最後。可上移、下移、編輯與確認刪除。第一站抵達時間＝出發時間＋該站交通分鐘；離開＝抵達＋停留；其餘站逐站累加。跨午夜須標示「次日」或「第 N 天」，並提示行程已跨日。總時數包含所有交通與停留；費用只加總輸入值，大於預算才顯示超支，等於預算不超支。調整順序後提醒重新確認各站交通估計，不能宣稱最佳路線。

保存與安全：localStorage 保存行程與每日設定，重新開啟還原。讀取須檢查欄位型別、範圍、日期與重複 ID；錯誤資料不能導致頁面當機。儲存失敗提醒資料只留在記憶體。提供 JSON 備份下載。使用 textContent 顯示使用者文字。地圖連結用 encodeURIComponent 編碼名稱與地址，開啟 Google Maps 搜尋，並標示需連網。沒有其他對外資料傳送。

簡報：第一頁可填姓名、學號與系級，下載帶有這三欄的 HTML。匯出檔不包含私人行程或外部字型。成果頁放實際操作截圖，未部署就明示未部署。紀錄真正執行的測試，不捏造使用者對話與操作歷程。

驗收：新增、空白輸入、時間累加、跨日提示、費用與預算邊界、編輯改日、調整順序、確認刪除、重新整理保存、手機寬度、換頁鍵與匯出檔重開。
04 / 迭代與實作檢查

讓規劃邏輯可以逐項驗證

實際需求迭代：初版採作業管理主題；使用者指定「旅遊景點規劃」後，重新設計欄位、行程計算與成果。以下另列規格補強及可用的修改指令範例。

規格補強 01

把移動時間算進去

只加總景點停留會低估一天所需時間，因此每站新增「到本站交通分鐘」，第一站也計入。

指令範例：「請把交通時間一起累加，顯示各站抵達與離開時間。」
規格補強 02

順序可調整，交通需重估

上移、下移後重新計算時間，並提醒使用者確認交通估計，避免把手動排序誤認成導航結果。

指令範例：「景點順序改變後，請重算時間並提示重新確認交通。」
規格補強 03

跨午夜不能只顯示時鐘

當行程延伸到隔天，時間旁加入跨日標記，避免將凌晨誤認成同一天。

指令範例：「超過午夜時請標示次日，並提醒行程過長。」

心得草稿

這次專題以旅遊景點規劃為主題，將原本分散的景點收藏整理成每日行程。規劃時發現，只列出景點名稱還不夠，必須一起考慮交通、停留時間與預估費用，才能判斷一天是否安排得太滿。

把需求寫給 AI 時，需要清楚定義時間如何累加、修改順序後如何更新，以及跨午夜和超出預算時如何提示。這些規則讓成果可以逐項檢查，也讓後續修改更有方向。

目前原型可整理行程，但交通時間與費用仍由使用者估算。後續希望加入地圖距離計算與多人共編；在真正出發前，仍需要確認各景點營業時間、交通與預約資訊。
